## 0.4.5 (2026-10-10)
- **Relationship bar vivid again (root cause found live via S1MCP).** The bar's `Band` graphic draws a coloured tier sprite ("Relationship band" — red/green/cyan tiles); its Image colour multiplies that sprite. The broad safety sweep tinted this graphic with the dark palette, turning the bright tiles into murky dark colours ("very very dark"). `ThemeRelationshipBar` restores a white tint (alpha preserved) on the `Band` graphic only and protects it from every later sweep. Verified nodes: `Topbar/Name/Relationship/{Background, Band}`. (A first blanket-whitening variant also whitened the scrollbar handle — a stray white square sat on the bar; the pass is now restricted to the sprite-carrying `Band` graphic.)
- **Order/counter-offer popup surfaces dark-themed.** The vanilla white quantity/price −/+ buttons and amount inputs clashed with the dark mode; the broad sweep skipped them because their node names trip the content-name guard ("item", "product", ...). `ThemeOrderPopups`/`ThemePopupSubtree` handle the popup subtrees explicitly: flat neutral-light fills go `GamePalette.CardAlt`, while content art (icons, locks, stars, portraits, product sprites) and coloured accents (green prices, blue Send button, the red over-limit counter) are never touched. The popup root is resolved automatically by walking up from the unique `ItemLimit` summary label, so it works regardless of which window hosts the popup (the dead-drop order window is not the `CounterofferInterface` root).
- **Text-guard fix ("Item Limit" unreadable).** `IsProtectedText` no longer applies the generic content-name guard to labels — names like "Item"/"Product" kept `Item Limit` dark while its surface was themed dark (dark on dark). Only genuinely special text nodes (avatar/portrait/notice/hint/timestamp/indicator/unread/badge) stay untouched. Verified in-game: the label renders bright white, identical to its sibling labels.
- **Same-frame dark-mode healing (`OnLateUpdate` + `AppTheme.FastPopupPass`).** Vanilla resets the popup's value texts/colours immediately on +/- clicks; the 1 s full-pass fallback (and a 0.2 s fast pass) left them visibly dark for about a second. The healing now runs once per frame after all Updates and before Unity paints, so the reset is repaired in the very frame it happens — zero visible delay. The pass does nothing unless an order popup is open.
- Verified in-game 2026-10-10 by Dominik: relationship bar vivid without the stray white handle, popup buttons/inputs dark, per-click updates without delay ("jackpot"); vanilla red over-limit counter visible and correct. Release build with deploy, 0 warnings/0 errors.

## 0.4.3 (2026-10-08)
- **Chat body background — root cause fixed:** the big vanilla-white area behind the message bubbles was never themed because `AppTheme.AsGraphic()` only handled `Graphic` and `GameObject`. `MSGConversation.scrollRectContainer` / `bubbleContainer` are plain `RectTransform`s (no Graphic of their own), so both lookups returned `null` and `TintChatBodyBackground` silently did nothing — the bubbles went dark, the surrounding area stayed white forever (the 1 s fallback "worked", it just had nothing to tint).
- **Verified against the real vanilla prefab** (Schedule I 0.4.7f12, `sharedassets0` "Conversation"): the white fill is `Conversation/ScrollContainer/ScrollRect/Viewport` — an opaque white `Image` (rgb 1,1,1, a 1) with a `Mask`, the node that actually covers the chat area. The container fields carry no Graphic at all.
- **`AsGraphic()`** now also accepts a general Unity `Component` (IL2CPP-safe `TryCast<Component>()` → `component.gameObject` → `GetComponent<Graphic>()`), so any RectTransform-shaped vanilla field resolves to the graphic its GameObject actually draws with.
- **`TintChatBodyBackground()`** resolves the surface in a guarded order: `conv.scrollRect.viewport` (the verified node) → the ScrollRect's own Graphic → a bounded `ScrollRect` lookup inside `conv.container` only when the field reference is not populated yet → the legacy container fields. The verified viewport is trusted on its own (Unity computes its rect at layout time — the prefab stores 0x0), while generic fallbacks must still pass the size gate.
- **Chat body is never mistaken for content/UI:** candidates must be near-neutral light (or already theme-owned), must not be a selectable/button surface (a row background can never be misread as the chat body), and the protected-name guard still applies. No overlays, no global scans, vanilla content untouched.
- **`ThemePageBackground()` coverage floor 0.85 → 0.80:** the real DialogueScreen page fills the screen while its conversation area is 100 px shorter (the Topbar), so the old cut rejected the genuine background. Sprite guard, largest-area selection and the protected-name checks are unchanged; selectable surfaces are now excluded there too.
- **Diagnostics:** one throttled summary line per pass — candidates / tinted / no-Graphic / skipped / overwritten (colour re-read after the pass to catch "tinted then overwritten") plus the resolved surface path. Per-candidate detail (node path, graphic type + instance id, original colour, rect size, skip reason, colour after tinting) is emitted only for the verified surface or a rejected candidate. Nothing is logged per frame.
- **Nothing else changed:** bubbles, texts, inbox rows, header, the vanilla order/counter-offer menus (still preserved), the injected search/filter band, hide/restore of conversations, and the original-colour caching + light-restore path in `AppTheme` all behave as before. Release build with deploy passed, 0 warnings/errors.

## 0.4.2 (2026-10-08)
- **Chat body background (open conversation):** the large vanilla-light area behind the message bubbles was never themed — the bubbles went dark but their surroundings stayed white. A new `TintChatBodyBackground` pass tints `MSGConversation.scrollRectContainer` and `bubbleContainer` (neutral-light only, normal restore path) and is called from `AppTheme.Apply` and from the conversation refresh, so a newly rendered message gets a dark chat body immediately.
- **Search also matches message text:** the live filter now checks the contact name AND the conversation's message history (`MSGConversation._messageHistory` → `Message.text`), so "OG Kush" or "dead drop" finds the thread even when the contact name does not contain it. Name-only match still wins; an unreadable history simply means no text match (never throws). The placeholder reads "Search name or text".
- **Dark-mode sync fixes (white artifacts):** three real bugs, not a timing nit.
  - The fallback theme pass ran every **20 s** — anything vanilla builds outside the patched methods (lazy `CreateUI`, message arrival, category switches) stayed vanilla-white for up to 20 s. Now **1 s**, and it stays cheap (cache-hit pass once tracked, only while the app is open).
  - `AppTheme.TryHandleSelectableTarget` bailed out with `return true` for any selectable-backed graphic that was *not* a themeable inbox-row ColorTint button — those surfaces were never tinted at all, by any pass. It now returns `false` so the normal tint path colours them.
  - Inbox-row colours were written only to the `ColorBlock`; Unity pushes `colors.normalColor` onto the graphic only during a state transition, so a row stayed vanilla-white until the pointer happened to hover or click it ("applies later"). The graphic colour is now written directly *and* the ColorBlock is themed, so hover/press still behave.

## 0.2.0 (2026-09-26)
- **Design rewrite — trash removed completely:** `TrashService`/`TrashUI` deleted; no trash UI, no trash toggle, no per-entry delete buttons and no trash persistence anymore. The v0.1.x `CreateConversationUI` patch (per-entry delete button) is gone.
- **Customer-only Clear All:** a single `[Clear All]` button (top-right of the vanilla MessagesApp home page) with a confirmation dialog ("Hide all N customer conversation(s) from the inbox? Supplier and dealer threads are kept."). Only conversations whose `Categories` contain Customer AND neither Supplier nor Dealer are hidden (`MSGConversation.SetEntryVisibility(false)`); supplier/dealer/unknown-category threads are never touched. Plan-then-commit iteration over `MessagesApp.ActiveConversations`, then `RepositionEntries()` + `RefreshNotifications()`. No trash records are written.
- **One-time legacy restore (`LegacyRestore`):** on `GameLifecycle.OnSaveInfoLoaded` and the `MessagesApp.Loaded` postfix (idempotent; deferred while the conversation lists are still empty) — (a) un-hides every conversation recorded in the old `trash_*.json[.bak]` files (match order: Id → Index+Name → name-only for `Index < 0` records) and renames each **fully restored** file to `*.restored` (only when the file parsed cleanly AND every record matched + un-hid — unmatched/unreadable files stay for a later load so no record can be burned; only the active save slot's files are touched); (b) safety net un-hides every hidden Supplier/Dealer conversation (never customers). Heals threads hidden by v0.1.x that the game save still persists (`MSGConversationData.IsHidden`).
- **Multiplayer:** Clear All and the legacy restore are host-only (`NetworkGuard.IsHostOrSingleplayer`); clients get a disabled `[Clear All]` button and mutations are ignored with a log warning.
- **Internals:** the `OnUpdate`/Tick dispatcher is gone (no per-frame work left); shared IL2CPP helpers (proxy liveness, conservative category filter, stable conversation id) live in `ConversationUtils`; the old UI lessons are kept in `ClearAllUI` (managed roots destroyed before rebuild, modal-card no-op button, `raycastTarget=false` on non-interactive graphics, modal reset on app close). `ModConfig` kept with the Phase 2/3 placeholder fields unchanged.

## 0.1.1
- Review fixes (behavior-preserving hardening; no feature changes).
- Fixed a skip bug in the purge re-apply (`ApplyToConversations`): list removal during forward iteration skipped adjacent purged threads, leaving them visible in the inbox. Both `Conversations` and `ActiveConversations` are now walked backwards.
- The trash UI now subscribes to `TrashService.OnTrashChanged` (once, static guard): Clear All / Restore / Empty trash / slot load immediately rebuild the "Trash (N)" row list instead of showing stale rows.
- Confirmation dialog: the modal root is part of the UI liveness check (dead buttons self-heal on the next open/tick), a no-op button on the dialog card stops backdrop click-through, and the dialog is reset on app close (no stale pending action reappears).
- Rebuild path destroys our own managed UI roots before re-injecting (no orphaned/duplicate toolbar after a mid-build failure).
- Purged threads are re-suppressed from the throttled tick, so a purged thread that receives a new message cannot resurrect its inbox entry (in-game test note in the README).
- Matching hardening: name-only fallback is restricted to records without a captured index (no cross-matching of duplicate contact names), and restore removes records by identity match instead of reference equality.
- Invisible panels/labels no longer swallow clicks meant for the vanilla UI (`raycastTarget` disabled on non-interactive graphics).
- Multiplayer clients now get disabled mutation buttons (read-only trash) instead of buttons that silently no-op.
- Slot probe fallback logs a warning (stale-slot-file risk is visible in the log).
- UI strings unified in English ("Trash (N)", "Empty trash").
