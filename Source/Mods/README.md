# Source/Mods — Mod Source Directory

All **active** mods and the shared library live here, one folder per project, and are built together through `S1Mods.sln`. Archived mods are in [`../Archive/`](../Archive/) and are not part of the solution. The authoritative inventory (status, versions, verification dates) is [`AGENTS.md`](../../AGENTS.md) §2; player-facing descriptions are in the root [README](../../README.md).

## Directory layout

```text
Source/Mods/
├── S1Mods.sln                  Generated by Tools/gen-sln.ps1 (deterministic GUIDs) — do not edit by hand
├── Directory.Build.props       Shared compiler settings + game/S1API/S1MAPI references for every project
├── Directory.Build.targets     Post-build deploy into the game directory (DLL/PNG/bundle → Mods\, json/pdb → UserData\<Mod>\)
├── README.md                   This file
│
├── Shared/                     S1Mods.Shared — common library referenced by every mod
│
├── AutoPackagingStation/       Automated packaging line (buildable, conveyor, quality mixing)
├── BankApp/                    Phone: banking dashboard
├── BusinessIncome/             Passive daily income for owned businesses
├── CalculatorApp/              Phone: decimal calculator
├── CustomSkateboard/           Pro Cyber Skateboard (physics, store injection, OBJ model)
├── HitmanPhone/                Bounty contracts via the Messages app
├── MessagesPlus/               Clear All + Trash for the vanilla Messages app
├── MoreSaveSlots/              25 save slots, pagination, renaming
├── NotesApp/                   Phone: notes
├── PocketShop/                 Phone: shop from anywhere
├── PotScanner/                 Phone: grow-pot monitor
├── StackLimitMod/              Configurable stack limits
├── TaxiDriver/                 Feasibility spike: NPC-driven taxi (developer tool)
└── Weather/                    Phone: weather dashboard
```

Every mod folder follows the same structure (scaffolded by `Tools/new-mod.ps1`):

```text
<ModName>/
├── src/
│   ├── <ModName>.csproj        Identity only (AssemblyName, RootNamespace) — everything else is inherited
│   ├── Mod.cs                  [assembly: MelonInfo(...)] + MelonMod entry point (MoreSaveSlots: MoreSaveSlotsMod.cs)
│   └── *.cs                    Mod code
├── docs/
│   ├── mod.json                Metadata (name, author, version, description, requires) → deployed to UserData\<ModName>\
│   ├── README.md               Player-facing documentation → copied into the release ZIP
│   └── CHANGELOG.md            Version history, newest first
├── assets/                     Optional: *.png icons, *.bundle, *.glb → deployed automatically
└── tests/                      Optional notes/fixtures; real test projects live in Source/Tests/
```

## Why every mod is isolated

- **One DLL per mod, independently installable.** Players pick single mods; nothing here depends on another mod at runtime.
- **No mod-to-mod references.** `Directory.Build.props` adds exactly one `ProjectReference` — to `Shared`. If two mods need the same code, it moves into `Shared`.
- **Own data folder.** Each mod persists under `UserData\<ModName>\` with slot-isolated files (`<name>_slot_{n}.json`), so mods never read or overwrite each other's state.
- **Own version.** Versions are bumped per mod (`Tools/bump-version.ps1`) and released as separate ZIPs (`Tools/package-release.ps1`).

The dependency rules are spelled out in [`docs/architecture.md`](../../docs/architecture.md).

## How the shared code works

`Shared/` compiles to `Shared.dll` (namespace `S1Mods.Shared`). It is referenced with `Private=false`, so it is **not** copied next to each mod — the build deploys one `Shared.dll` into `<GameDir>\Mods\`, and release ZIPs include it as well.

| Component | Purpose | Used by (examples) |
|---|---|---|
| `SafeStorage` | Atomic JSON/text save with `.tmp` staging, `.bak` backup and tolerant load | NotesApp, BankApp, CalculatorApp, BusinessIncome, StackLimitMod, HitmanPhone, MessagesPlus, MoreSaveSlots, AutoPackagingStation |
| `SaveSlots` | Resolves the active save slot (`slot_{n}` suffix, guards against `slot_-1`) | NotesApp, CalculatorApp, BusinessIncome, HitmanPhone, MessagesPlus, AutoPackagingStation |
| `UITheme` | Responsive uGUI scaling for the rotated high-DPI phone canvas (`Sp`, `Dp`, `InitializeForTextApp`, `InitializeForDashboard`) | all phone apps, MessagesPlus |
| `PatchGuard` | Harmony patching with signature validation and graceful degradation (`TryPatch`, `Report`) | StackLimitMod, CustomSkateboard, MessagesPlus, HitmanPhone, AutoPackagingStation, TaxiDriver |
| `NetworkGuard` / `SceneGate` | Host-authority checks (`IsHostOrSingleplayer`), main-scene guard, safe in-scene execution | BusinessIncome, PotScanner, BankApp, PocketShop, HitmanPhone, AutoPackagingStation (SceneGate) |
| `ModConfig<T>` | Typed MelonPreferences wrapper with auto-save and change events | PotScanner, CustomSkateboard, PocketShop, BankApp, BusinessIncome, MessagesPlus |
| `ModLogger` | `[ModName]`-prefixed logging (`Info`, `Warn`, `Error`, `Debug`) | most mods (e.g. BankApp, PocketShop, HitmanPhone, TaxiDriver) |
| `SafeInvoker` | try/catch wrapper for callbacks so one failing handler cannot stop the Unity loop | used internally by `SceneGate`; covered by `Shared.Tests` |
| `HotkeyManager` | Allocation-free hotkey router with modifier handling and InputField focus protection | AutoPackagingStation |
| `GameObjectResolver`, `TypeResolver` | Cached deep component search; type lookup across loaded assemblies | AutoPackagingStation (`TypeResolver`); `GameObjectResolver` currently unused by active mods |
| `EconomyHelper`, `AudioHelper`, `ShopListingSync` | Money helpers, sound playback, shop-listing synchronisation | BankApp (`EconomyHelper`, `AudioHelper`), PocketShop (`AudioHelper`), AutoPackagingStation (`AudioHelper`, `ShopListingSync`) |

Changing `Shared` affects every mod: build the whole solution and run `Source/Tests/Shared.Tests` afterwards.

## Naming conventions

| Item | Convention | Example |
|---|---|---|
| Mod folder, csproj, AssemblyName, `MelonInfo` name, `mod.json` `name` | identical PascalCase | `PotScanner` |
| Root namespace | mod name (Shared: `S1Mods.Shared`) | `namespace PotScanner` |
| Entry class | `Mod : MelonMod` in `Mod.cs` (historic exception: `MoreSaveSlotsMod`) | `PotScanner.Mod` |
| Icon | `assets/<lowercase>_icon.png` for new mods; existing names are kept for compatibility | `weather_icon.png`, `PotScannerIcon.png` |
| Persisted files | `UserData\<Mod>\<name>_slot_{n}.json` | `notes_slot_1.json` |
| Console command word | short lowercase noun | `pot`, `biz`, `stack`, `skate`, `pshop`, `taxi` |
| Versions | SemVer `MAJOR.MINOR.PATCH`, optional pre-release suffix | `1.0.12`, `0.1.0-beta.1` |

## Versioning

The code is the single source of truth: `[assembly: MelonInfo(typeof(X.Mod), "X", "1.2.3", "Dominik")]` (PotScanner: `Constants.ModVersion`). `Tools/bump-version.ps1 -Mod X -Version 1.2.4` synchronises `docs/mod.json`, `docs/CHANGELOG.md`, `AGENTS.md` and the root `README.md`; `Tools/check-version-sync.ps1` fails CI on any drift. Changelogs use `## x.y.z (YYYY-MM-DD) — short title` headers with the newest version first.

## mod.json

```json
{
    "name": "NotesApp",
    "author": "Dominik",
    "version": "1.0.3",
    "description": "In-game phone Notes app (...)",
    "requires": ["S1API"]
}
```

`mod.json` is metadata for players and tooling (`package-release.ps1` reads `version` for the ZIP name). It is deployed to `UserData\<Mod>\mod.json` — never to `Mods\`. `requires` is informational; the actual assembly references come from `Directory.Build.props`.

## Assets

- `assets/*.png` → `<GameDir>\Mods\` (phone-app icons; the app registers the file name).
- `assets/*.bundle` → `<GameDir>\Mods\`.
- `assets/*.glb` → `<GameDir>\Mods\<Mod>\` (data sub-folder; MelonLoader only scans DLLs in `Mods\`). Example: `TaxiDriver/assets/taxi.glb`.
- Source files for assets (Blender scenes, generator scripts) may live next to them, e.g. `CustomSkateboard/assets/models/` and `generate_skateboard.py`.
- Screenshots for the root README belong in [`assets/`](../../assets/README.md) at the repository root, not in the mod folder.

## Tests

- `Source/Tests/<Mod>.Tests/` — xUnit projects picked up by `gen-sln.ps1`. Pure-logic tests link the source file directly (`<Compile Include="..\..\Mods\AutoPackagingStation\src\PackagingMath.cs" />`) so they run without game assemblies — this is how `AutoPackagingStation.Tests` and `CalculatorApp.Tests` run in CI.
- `Source/Tests/Shared.Tests/` references the real MelonLoader/Unity DLLs and only runs on a machine with the game installed.
- Keep testable logic (math, state machines, parsers) in plain static classes without Unity or S1API types so it can be linked into a test project.

## Build system essentials

```pwsh
dotnet build Source/Mods/S1Mods.sln -c Release                     # all projects, deploys to the game
dotnet build Source/Mods/NotesApp/src/NotesApp.csproj -c Release   # one mod
dotnet build Source/Mods/S1Mods.sln -c Release -p:S1NoDeploy=true  # compile only
pwsh Tools/gen-sln.ps1                                             # after adding/removing a project
```

- Target framework `net6.0`, C# 12, nullable enabled, portable PDBs (`Directory.Build.props`).
- Game path: `$env:SCHEDULE1_PATH`, fallback `C:\Program Files (x86)\Steam\steamapps\common\Schedule I`.
- IL2CPP requirements that apply to every project are listed in [`docs/pitfalls.md`](../../docs/pitfalls.md) §1; the full developer workflow is in [`DEVELOPERS.md`](../../DEVELOPERS.md).
